# CrossFit Web

Responsive React and Vite PWA for the CrossFit training application.

## Structure

- `src/app`: application composition and the root component.
- `src/features`: user-facing capabilities, added when each feature is implemented.
- `src/shared`: reusable UI, API and utility code, added only when shared by multiple features.

## API access

The app calls the backend under `/api/v1`. In development, Vite proxies `/api` to `http://localhost:3000`; set `VITE_API_BASE_URL` at build time to point to a different base path.

## Offline execution drafts

Planned sessions can be copied into IndexedDB as execution drafts before any network request. Draft and nested block IDs are UUIDv7 generated by the PWA. Local edits remain `pending` until a complete snapshot is accepted by `PUT /api/v1/session-executions/{executionId}`; failed writes stay available for retry instead of being discarded.

Opening a planned session hydrates the draft already stored for it, so the athlete can continue where they left off. The **Mis registros** tab lists every stored draft with its synchronization state:

- planned drafts reopen in the weekly planning view, on the week and session they belong to;
- free trainings are created without a planned session and edited locally (title, date, general note and blocks with type, title, status and notes).

## Progress

The top-level **Progreso** tab groups two views:

- **Marcas**: pending suggestions, current personal records, paginated history and manual historical records for movements and complex versions.
- **Volumen**: accumulated repetitions, bar volume, technical practice time, sessions and last practice date for 4 weeks, 12 weeks, the last year or a custom range. The breakdown can group by movement or movement family.

The volume view calls `GET /api/v1/progress/volume`; it only counts completed sessions and attempts and explains that complex volume is not attributed to a movement.

Technique blocks show an optional **Tiempo (s)** field for each set. The value is stored as `durationSeconds` in the execution snapshot and included in the attempt summary.
